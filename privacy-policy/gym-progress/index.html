2. GELTUNGSBEREICH UND GRUNDSÄTZE

Diese Datenschutzerklärung gilt für die Android-App „Gym Progress“ mit dem Paketnamen:

eu.realityforge.gymprogress

Gym Progress ist eine lokal ausgerichtete App zur Planung und Organisation von Trainingseinheiten. Die App kann ohne Benutzerkonto genutzt werden.

RealityForge verlangt für die Nutzung der App grundsätzlich keine Registrierung und keine Angabe von Name, E-Mail-Adresse, Telefonnummer oder Passwort.

Der überwiegende Teil der Trainingsdaten wird ausschließlich im privaten App-Speicher des Geräts verarbeitet. Ein Cloud-Sync der Trainingspläne findet nicht statt.

Gym Progress nutzt je nach Funktion:

  • lokalen Gerätespeicher für Trainingspläne, Übungseinstellungen, Kurse, benutzerdefinierte Übungen, Notizen, Erinnerungs- und App-Einstellungen;
  • Google Analytics for Firebase für optionale Nutzungsanalyse nach ausdrücklicher Einwilligung;
  • Google AdMob für Banner- und Interstitial-Werbung in der kostenlosen Version;
  • Google User Messaging Platform (UMP) zur Verwaltung von Werbe-Datenschutzentscheidungen;
  • Google Play Billing für einmalige Käufe („Werbefrei“ und „Pro“);
  • den eingebetteten YouTube-Player im erweiterten Datenschutzmodus für freiwillig geöffnete Bewegungsvideos;
  • einen separaten Cloudflare-Worker mit D1-Datenbank für freiwilliges Feedback zu Bewegungsvideos.

Gym Progress verwendet derzeit nicht:

  • Benutzerkonten;
  • Firebase Authentication;
  • Cloud Firestore für Trainingsdaten;
  • Cloud-Synchronisation von Trainingsplänen;
  • Firebase Crashlytics;
  • Firebase Performance Monitoring;
  • Firebase Cloud Messaging;
  • Abonnements.

Android-Cloud-Backup für die privaten App-Daten ist deaktiviert.

RealityForge verkauft keine personenbezogenen oder sensiblen Nutzerdaten.

3. LOKAL AUF DEM GERÄT GESPEICHERTE DATEN

Gym Progress speichert für die Nutzung der App insbesondere folgende Informationen lokal im privaten App-Speicher oder in app-eigenen lokalen Einstellungen:

  • ausgewählte App-Sprache;
  • ein aus dem lokal eingegebenen Geburtsdatum abgeleitetes Datum, ab dem bestimmte optionale Onlinefunktionen für das Profil verfügbar sein können; das eingegebene Geburtsdatum selbst wird nicht gespeichert oder an RealityForge bzw. Drittanbieter übertragen;
  • Trainingsnamen;
  • Zuordnung von Übungen zu Wochentagen;
  • Reihenfolge der Übungen;
  • Cardio-Werte für Warm-up, Zone 2 und Cool-down;
  • Trainingsgewicht;
  • Einstellung „ohne Zusatzgewicht“;
  • Anzahl der Sätze;
  • minimale und maximale Wiederholungen;
  • gewählte Schwierigkeit bzw. Anstrengung;
  • Trainingsdauer bei Cardio-Übungen;
  • für den jeweils aktuellen lokalen Kalendertag den Abhakstatus von Übungen;
  • Kurse eines Trainingstags, einschließlich interner Kurs-ID, Kursname, optionaler Startzeit, optionaler Dauer, optionalem Ort und optionaler Notiz;
  • für den jeweils aktuellen lokalen Kalendertag den Abhakstatus von Kursen;
  • selbst eingegebene Namen und Reihenfolge der Gegenstände in der Sporttaschen-Vorlage sowie deren aktuellen Abhakstatus;
  • freiwillig eingegebene Freitextnotizen mit Titeln;
  • Einstellungen für lokale Benachrichtigungen;
  • Zeit der letzten App-Nutzung für Inaktivitätserinnerungen;
  • Datum der ersten Nutzung sowie Anzahl unterschiedlicher aktiver Nutzungstage für die zeitverzögerte Aktivierung von Interstitial-Werbung;
  • lokale Statusdaten für die Begrenzung von In-App-Review-Anfragen;
  • lokale Analytics-Einwilligungsentscheidung;
  • gegebenenfalls von UMP lokal verwaltete Werbe-Datenschutzentscheidungen;
  • bei Nutzung des Video-Feedbacks eine zufällig erzeugte Installations-ID, die ausschließlich für diese Feedback-Funktion verwendet wird;
  • technische Informationen zur Versionierung und Migration des lokalen Speicherformats.

Der Abhakstatus von Übungen und Kursen wird nicht als dauerhafte Trainingshistorie geführt. Die aktuelle Implementierung berücksichtigt nur den Status für ein einziges lokales Kalenderdatum. Ein Status eines früheren Datums wird nicht als aktuelle Erledigung interpretiert und wird bei der lokalen Normalisierung bzw. weiteren Nutzung zurückgesetzt.

Ältere Installationen können aus früheren App-Versionen weiterhin lokal gespeicherte Legacy-Daten enthalten, insbesondere frühere Workout-History-Einträge. Diese können aus Kompatibilitätsgründen im lokalen Datenbestand verbleiben, werden von der aktuellen App aber nicht als neue Trainingshistorie fortgeschrieben.

Die lokalen Trainingsdaten werden nicht an ein RealityForge-Benutzerkonto übertragen und nicht mit einem RealityForge-Server synchronisiert.

RealityForge kann die im privaten App-Speicher gespeicherten Trainingsdaten nicht aus der Ferne abrufen.

Freitextfelder wie Trainingsnotizen oder Kursnotizen sind für trainingsbezogene Angaben vorgesehen. Nutzer entscheiden selbst, welche Inhalte sie dort lokal speichern. RealityForge erhält diese lokalen Freitexte nicht automatisch.

4. BENUTZERDEFINIERTE ÜBUNGEN („CUSTOM EXERCISES“)

Gym Progress Pro ermöglicht das Erstellen eigener Übungen.

Je nach Nutzung können dabei lokal gespeichert werden:

  • eine zufällig erzeugte interne Übungs-ID;
  • der vom Nutzer eingegebene Übungsname;
  • ausgewählte Muskelgruppe/Kategorie;
  • optionale YouTube-Video-ID und Startzeit;
  • Einstellung „mit/ohne Zusatzgewicht“;
  • die zugehörigen Übungseinstellungen, einschließlich einer gegebenenfalls eingestellten Cardio-Dauer;
  • ein optional ausgewähltes eigenes Bild.

Für die Bildauswahl nutzt die App den Android-System-Picker. Eine allgemeine Berechtigung zum Zugriff auf die gesamte Foto- oder Mediendatenbank ist dafür nicht erforderlich.

Ein ausgewähltes Bild wird aus dem vom Nutzer freigegebenen Inhalt gelesen, lokal im privaten App-Speicher neu verarbeitet, gegebenenfalls verkleinert und als app-eigene PNG-Datei gespeichert. Dabei werden die ursprünglichen Dateimetadaten nicht als solche in die neu erzeugte Datei übernommen; insbesondere übernimmt die App keine EXIF- oder GPS-Metadaten in die neu encodierte PNG-Datei.

Benutzerdefinierte Übungen und deren Bilder werden nicht automatisch an RealityForge übertragen.

5. TRAININGSDATEN IMPORTIEREN UND EXPORTIEREN

Gym Progress bietet einen manuellen CSV-Import und CSV-Export der Trainingsdaten.

Der Export kann insbesondere enthalten:

  • alle sieben Trainingspläne;
  • Trainingsnamen;
  • Übungsreihenfolge;
  • Cardio-Werte;
  • Übungseinstellungen einschließlich Cardio-Dauer;
  • Kurse einschließlich Name, optionaler Startzeit, optionaler Dauer, Ort und Kursnotiz;
  • Namen und Reihenfolge der Gegenstände in der Sporttaschen-Vorlage, jedoch nicht deren aktuellen Abhakstatus;
  • Titel und Inhalte der freiwillig eingegebenen Freitextnotizen;
  • benutzerdefinierte Übungen;
  • bei benutzerdefinierten Übungen gegebenenfalls lokal eingebettete Bilddaten.

Der aktuelle Tages-Abhakstatus von Übungen und Kursen wird nicht als Trainingshistorie exportiert.

Der Export wird lokal auf dem Gerät erzeugt. Der Nutzer entscheidet über den Android-Dateidialog, wo die Datei gespeichert wird.

Der Import wird ebenfalls lokal verarbeitet. Importierte Dateien werden vor Übernahme technisch validiert und begrenzt.

RealityForge erhält den Inhalt der Export- oder Importdatei nicht.

Wählt der Nutzer im Android-Dateidialog einen externen Dokumentanbieter oder Cloud-Dienst, kann dieser Anbieter die Datei nach seinen eigenen Datenschutzbestimmungen verarbeiten. Dies wird durch die Auswahl des Nutzers veranlasst und liegt außerhalb des Zugriffs von RealityForge.

7. LOKALE BENACHRICHTIGUNGEN

Gym Progress kann lokale Benachrichtigungen für:

  • Trainingstage;
  • längere Inaktivität;
  • die neue Trainingswoche

planen.

Bei einer neuen Installation sind diese drei Reminder-Einstellungen app-intern standardmäßig aktiviert. Eine tatsächliche Zustellung ist auf Android-Versionen mit Laufzeitberechtigung nur möglich, wenn die Android-Benachrichtigungsberechtigung erteilt wurde.

Wird die Systemberechtigung nicht erteilt, werden keine entsprechenden Benachrichtigungen zugestellt. Die app-internen Reminder-Einstellungen können dabei weiterhin als aktiviert gespeichert bleiben und vom Nutzer jederzeit geändert werden.

Ob und in welchem Umfang Benachrichtigungsinhalte auf dem Sperrbildschirm sichtbar sind, richtet sich zusätzlich nach den Android-Systemeinstellungen des Nutzers.

Die Reminder werden lokal über Android-Systemmechanismen geplant. Trainingsdaten werden dafür nicht an RealityForge übermittelt.

Gym Progress verwendet für diese Reminder kein Firebase Cloud Messaging und keinen serverseitigen Push-Dienst.

13. FREIWILLIGES FEEDBACK ZU MOVEMENT-GUIDE-VIDEOS

Diese Onlinefunktion ist bei unbekanntem Alter und für Profile unter 21 Jahren nicht verfügbar.

Nutzer können freiwillig:

  • ein nicht funktionierendes Video melden;
  • eine falsche Übung oder Gerätevariante melden;
  • eine schlechte Übereinstimmung bzw. Ausführung melden;
  • ein besseres YouTube-Video vorschlagen.

Eine Übertragung erfolgt nur, wenn der Nutzer die Meldung aktiv absendet.

Übertragen werden:

  • Exercise-ID;
  • aktuelle YouTube-Video-ID;
  • ausgewählter Meldegrund;
  • bei einem Ersatzvorschlag die vorgeschlagene YouTube-Video-ID;
  • App-Version;
  • ausgewählte App-Sprache;
  • eine zufällig erzeugte, ausschließlich für diese Feedback-Funktion verwendete Installations-ID.

Eine eingegebene YouTube-URL wird vor der Übertragung auf die Video-ID reduziert.

Nicht mitgesendet werden insbesondere:

  • Trainingsnamen;
  • Kursdaten;
  • Trainingsgewichte;
  • Wiederholungen;
  • Sätze;
  • vollständige Trainingspläne;

  • selected report reason;

  • app version;
  • selected app language;
  • a randomly generated installation ID used exclusively for this feedback feature.

A YouTube URL entered by the user is reduced to the video ID before transmission.

In particular, the following is not sent:

  • workout names;
  • course data;
  • workout weights;
  • repetitions;
  • sets;
  • complete workout plans;
  • search terms;
  • Google account;
  • Advertising ID;
  • Firebase app-instance ID;
  • free-text notes.

The local feedback installation ID is randomly generated when the feedback feature is first used.

The Cloudflare Worker uses HMAC-SHA-256 with a secret stored only on the server to calculate a pseudonymous hash. The raw installation ID is not stored in the D1 database.

Current abuse-protection limits are:

  • no more than 5 stored reports per exercise and installation within a rolling 24-hour period;
  • no more than 200 stored reports per installation within a rolling 24-hour period;
  • identical reports from the same installation, exercise, reason and suggested video ID are not stored as a separate queue entry again within 30 days.

The Android dialog also prevents concurrent duplicate submissions while a request is in progress. There is no general time-based 10-minute cooldown.

Cloudflare provides the Worker and D1 database infrastructure. As an infrastructure provider, Cloudflare necessarily processes network connection data such as IP addresses. RealityForge does not store a raw IP address in D1 for this feature and does not create a device fingerprint.

Reports are moderated internally by RealityForge. An accepted suggestion does not automatically change the exercise catalogue.

The legal basis is Article 6(1)(f) GDPR. RealityForge’s legitimate interest is to identify broken or unsuitable movement guides, improve app quality and protect the feedback infrastructure against abuse.
